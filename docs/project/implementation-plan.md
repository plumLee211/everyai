# Plan: 영상의 빈틈을 찾는 AI 배리어프리 점검 도구 (Python + PyQt6, Windows)

**Source PRD**: 별도 PRD 문서 없음. 이 문서가 요구사항을 겸한다. PRD 지표는 아래 "성공 지표"에 직접 옮겨 적었다.

**Selected Milestone**: M1~M3 전체 (자막 점검 → 화면 전용 정보 점검 → 사람 확인과 결과 정리)

**Complexity**: Large

**Status**: DRAFT (검토 반영본 v2). 구현은 아직 시작하지 않음. **코드보다 평가 기준 수립(Phase -1)을 먼저 한다.**

## Summary

공공기관 영상 편집자가 영상(최대 20분, 1건씩)과 자막 파일을 넣으면, ffmpeg로 오디오·프레임을 추출하고 faster-whisper(받아쓰기)와 OCR(화면 글자)로 음성·화면 글자를 얻어 자막과 교차 비교한다. 누락·불일치·화면 전용 정보를 구간별 목록으로 보여 주고, 편집자가 확정/기각한다. 자막 파일이 없으면 OCR로 영상 속 자막 영역을 찾아 편집자가 확인한 뒤 자막을 만들어 같은 절차를 진행한다.

이 도구가 하는 일은 세 가지로 한정한다.

- **M1**: 음성과 자막의 핵심 정보(날짜·시각·금액·연락처·수치) 일치 검증
- **M2**: 화면의 주요 문자 정보가 음성으로 전달되는지 검증, 화면을 봐야 이해되는 구간 안내
- **M3**: 사람이 빠르게 검수하는 작업 환경

행동 인식, 장면 분석, 효과음 인식, 비문자 시각 정보의 설명 누락 판정은 하지 않는다(향후 확장).

## 성공 지표

아래 수치는 **실험으로 확인된 성능이 아니라 검증 전 목표값**이다. Phase -1의 정답 데이터로 측정한 뒤 조정한다.

- 탐지율 80% 이상 (평가 영상의 정답 "오류" 대비)
- 정밀도 60% 이상. 이는 발견한 오류 10개 중 4개가 거짓 지적일 수 있다는 뜻이므로, **이 수준에서 실제 검수 시간이 줄어드는지**가 핵심 검증 질문이다. 줄지 않으면 목표 정밀도를 다시 정한다.
- 정밀도·탐지율은 결과 상태가 "오류"인 항목으로만 계산한다. "검수 필요"와 "판단 불가"는 개수와 확인에 쓴 시간을 따로 잰다.
- 함께 측정할 것:
  - 영상당 검수 소요 시간 (도구 사용 vs 직접 검수)
  - 불필요한 확인 횟수 (기각된 항목 수)
  - 평가자 간 일치율
- 결과는 영상 형식별(홍보, 정책 안내, 교육)로 나누어 보고한다.

### 하드웨어 전제

- faster-whisper(CTranslate2)의 GPU 가속은 NVIDIA CUDA만 지원한다. 내장 그래픽과 Mac은 CPU로 실행한다. easyocr(torch)도 CPU 기준으로 설계한다.
- 설계 목표: **CPU만 있는 Windows PC에서 20분 영상이 현실적인 시간 안에 끝나는 것.**
- 서버 처리 부담을 없앤 것이 아니라 **사용자 PC로 옮긴 것**이다. 처리 시간은 Task 0에서 실측한다.
- 범위 밖: 사양 기반 자동 추천(코어·RAM 등급), 내장 그래픽 가속(OpenVINO, DirectML), 실행 시 자동 벤치마크.

## 권리·데이터 처리

- 모델을 추가로 학습(파인튜닝)하지 않는다. 사전학습 모델(faster-whisper, OCR)로 **로컬에서 추론만** 한다.
- 영상과 분석 결과는 사용자 PC 밖으로 전송하지 않는다.
- 평가용 영상은 공공누리 유형 또는 별도 이용허락을 확인한 뒤 사용하고, 출처와 이용 조건을 `tests/eval/`에 기록한다.
- 외부 AI 서비스로 영상을 보내는 기능을 추가하려면 별도의 권리·보안 검토가 필요하다.
- 한계: 로컬 추론이라는 사실만으로 모든 권리 문제가 해결되지는 않는다. 모델 라이선스와 영상의 이용 조건은 각각 확인한다.

## 요구사항 정리

- 입력: 영상 1건(≤20분), 자막 파일(SRT 우선, 선택)
- 처리: 음성(받아쓰기) / 자막 / 화면 글자(OCR)를 추출해 교차 비교
  - M1: 음성↔자막 핵심 정보 일치 검증
  - M2: 화면의 주요 문자 정보가 음성으로 전달되는지 점검, 화면 의존 표현 구간 안내
  - M3: 구간별 목록, 영상 이동, 확정/기각, 요약

| 구분 | 이번 구현 | 주로 해결하는 문제 | 향후 확장 |
|---|---|---|---|
| M1 | 음성 대사 ↔ 자막의 핵심 정보 일치 검증 | 청각장애인 등의 정보 접근성 | 화자 표시, 효과음·음악 등 소리 정보 |
| M2 | 화면의 주요 문자 정보(날짜, 장소, 연락처, 금액, 수치·비율)가 음성으로 전달되는지 점검 + 화면 의존 표현 구간 안내 | 시각장애인의 정보 접근성 | 행동, 몸짓, 그래프 의미, 장면 변화 등 비문자 시각 정보 |
| M3 | 문제 구간 검수 및 결과 정리 | 영상 편집자의 업무 효율 | — |

**범위와 주장의 경계** (심사·발표 시 이 표현을 기준으로 한다)

- M2는 "화면해설 누락 판정"이 아니라 "화면에 표시되는 주요 문자 정보가 음성으로 충분히 전달되는지 확인"하는 기능이다.
- 예: 화면에 "2025년 30%, 2026년 60%" 그래프가 있고 음성이 "상당히 증가했습니다"뿐이면, 수치 30%·60%가 음성에 없다는 점을 지적한다. 그래프가 말하는 증가의 의미가 충분히 전달됐는지는 판단하지 않고 사람이 확인한다.
- 예: 화면에서 손짓으로 비상구를 가리키고 음성이 "이쪽으로 이동하시면 됩니다"뿐이면, 장면은 분석하지 못한다. 대신 "이쪽으로" 같은 지시 표현을 근거로 "화면을 봐야 이해되는 구간, 확인 필요"로 안내한다.
- 제외: 자막 편집, 화면해설(TTS), 소리 정보 제안, 장면 분석, 행동 인식, 효과음 인식, 다건 처리, 사양 자동 추천, 내장 그래픽 가속

## Phase -1. 평가 기준 수립 (P0, 코드 작업 전)

모델이 찾은 것을 정답으로 착각하지 않도록, 사람이 먼저 정답을 정한다. 이 과정 없이 임계값을 정하면 잘못된 판정 기준 위에서 코드만 정교해진다.

1. **평가 영상 3편**: 홍보영상, 정책 안내영상, 교육영상처럼 형식이 다른 공공기관 영상을 고른다. 공공누리 유형 또는 이용허락을 확인하고 출처를 기록한다.
2. **접근성 기준 선정과 대응표**: KWCAG 2.2의 자막·대체 콘텐츠 항목, WCAG 1.2, 방송통신위원회의 장애인방송 가이드라인을 후보로 둔다. 정확한 문서명과 조항은 원문으로 확인한다. 화면해설·배리어프리 자막 관련 논문과 가이드라인을 읽고, 각 기준을 "다룸 / 부분적으로 다룸 / 다루지 않음"으로 표시하는 대응표를 만든다. 전문지식 전부를 갖추는 것이 목적이 아니라, 구현 가능한 기준과 아직 다루지 못하는 기준을 구분하는 것이 목적이다.
3. **정답 판정 원칙 문서** (`tests/eval/annotation_guide.md`): 어떤 구간을 오류·검수 필요로 볼지 예시와 함께 정한다. 예: "표현만 다르고 값이 같으면 정상", "다른 시점에 언급돼도 표시 시점에 설명이 없으면 검수 필요".
4. **독립 평가 2인**: 팀원 2명이 같은 영상을 따로 표시하고 일치율을 잰다(단순 일치율, 가능하면 Cohen's kappa). 불일치 구간은 합의해 정답을 확정하고 판정 원칙을 보완한다.
5. **산출물**: 영상 3편의 정답 파일(`tests/eval/*.json`), 판정 원칙 문서, 기준 대응표, 평가자 간 일치율.
6. 임계값은 이 정답으로만 조정한다. Task 0 실측도 이 영상들로 한다.

## 결과 상태

자동 판정 결과(`Verdict`)와 편집자의 처리 상태(`ReviewStatus`)를 별도 필드로 둔다.

| 자동 판정 | 상황 |
|---|---|
| 오류 | STT 신뢰도 충분 + 음성의 핵심 값이 자막에 없거나 다름, 자막 후보 없음, 화면의 중요 정보가 영상 전체에서 말해지지 않음 |
| 검수 필요 | 표현 차이(값 없는 문장), 화면 의존 표현(M2-2), 표시 시점과 다른 곳에서 언급됨, 영상 내내 표시되는 중요 정보, OCR 생성 자막 모드의 M1 결과 |
| 판단 불가 | STT 신뢰도 낮음(`avg_logprob`·단어 확률 기준) → "자동 판단 불가: 음성 확인 필요", OCR 신뢰도 낮음 → "화면 확인 필요" |

- STT의 인식 신뢰도와 자막 불일치 판정의 신뢰도는 다르다. 음성 인식이 불확실하면 자막이 틀렸다고 말할 근거도 부족하므로, 심각도를 낮추는 대신 "판단 불가"로 분리한다.
- 편집자의 처리 상태는 확정 / 기각 / 보류다.

## 판정 로직

### 공통 정규화

NFKC, 소문자화, 공백·구두점 제거. 날짜·시각·전화번호·금액 문맥에서 한국어 수사를 숫자로 변환("삼월 십오일"→"3월15일"). 시각은 하나의 형태로 통일한다("오후 세 시 삼십 분", "15:30", "오후 3시 30분" → `15:30`). whisper는 숫자를 이미 아라비아 숫자로 내보내는 경우가 많고 자막에는 한글 수사가 쓰이기도 하므로, **음성·자막·화면 글자 모두 같은 규칙으로 양방향 정규화**한다. 고유어 수사("스무 명", "다섯 시")와 범위 표현("~", "부터…까지")도 변환 표에 포함한다.

### 중요 정보 (규칙 기반, LLM 미사용)

1. 날짜·요일·시각·기간
2. 장소: `시/구/동/로/길/층/호/센터/관/청/역` 접미 패턴. 일반 단어 오탐("감동", "공감", "역할")이 많으므로 **좁게 시작**한다. 어간 최소 길이, 주소 패턴(`OO시 OO구`), 숫자와 결합한 `층/호`부터 적용한다.
3. 전화번호·URL
4. 금액·인원
5. 수치·비율: `30%`, `60퍼센트`, `2배`, `3천 명`처럼 숫자+단위/퍼센트 패턴, 증감 수치. 그래프·표 속 숫자가 여기에 해당한다. 숫자 단독(연도 등)은 날짜 규칙과 겹치므로 중복 처리하지 않는다.

### 자막 소스 결정 (결정 2)

- 자막 파일이 있으면 그것을 사용한다.
- 없으면 하단 글자를 곧바로 자막으로 보지 않는다. 담당자 이름, 기관명, 행사 장소, 안내 문구도 하단에 표시되기 때문이다. 다음 절차를 거친다.
  1. **영역 단위 판단** (`subtitle_region.py`): 프레임 하단 후보 영역(초기값: 높이의 하단 25%)이 자막 트랙인지 영역 전체로 판단한다. 신호는 글자가 자주 바뀌는 정도, 표시 구간이 발화 구간과 겹치는 정도, 영역 전체로 보았을 때 STT 내용과 일치하는 정도다. **줄 단위로 STT와 맞는지 보아 자막 여부를 정하지 않는다.** 틀린 자막이 "자막 아님"으로 빠져 M1 대상에서 사라지는 순환 판정이 되기 때문이다.
  2. **편집자 확인**: 분석 전에 자막으로 추정한 영역과 대표 프레임 몇 장을 보여 주고, "맞음 / 영역 조정 / 영상에 자막 없음" 중 하나를 고르게 한다.
  3. 확인된 영역의 글자만 자막 후보로 보고, 연속 프레임의 같은 글자를 하나의 구간으로 병합해 `SubtitleCue`와 SRT 파일을 생성한다. "OCR로 추출한 자막으로 점검합니다"라고 표시한다.
  4. 자막 영역에서 제외된 글자(이름, 기관명, 장소 등)는 M2의 화면 글자로 남긴다.
- **자막 영역 OCR은 별도로 더 촘촘하게 샘플링**한다(2~4fps 검토). 1fps로는 자막 시점이 ±1초 어긋나고 1초 미만 자막을 놓친다. 일반 화면 글자(M2)는 1fps를 유지한다.
- OCR은 영상당 한 번만 실행하고, 영역별로 결과를 나눈다.
- 주의: OCR 생성 자막은 OCR 오류가 섞인다. 이 모드의 M1 결과는 모두 "검수 필요"로만 표시하고 "오류"로 판정하지 않는다.
- **자막 파일도 없고 영상 속 자막도 없는 경우**: 개별 지적을 만들지 않고 "자막이 없는 영상입니다" 한 건으로 요약한다.

### M1: 음성↔자막 (2단 구조)

글자 일치율은 판정 기준이 아니라 **보조 신호**다. 자막은 발화를 그대로 옮기지 않을 수 있어서, 문자 차이가 커도 의미가 같은 문장에 일치율은 취약하다.

1. **후보 자막**: `[시작−2.0s, 끝+2.0s]`와 겹치는 자막. 겹침이 없으면 ±6s로 한 번 넓힌다.
2. **노이즈 억제**: `no_speech_prob`가 높거나 3자 미만인 구간 제외.
3. **판단 불가 확인**: STT 신뢰도가 낮은 구간은 "판단 불가: 음성 확인 필요"로 분리하고 이후 단계를 진행하지 않는다.
4. **1단 (판정, 값 비교)**: 음성과 후보 자막에서 중요 정보를 추출·정규화해 값을 비교한다. 음성의 값이 자막에 없으면 "값 누락", 다르면 "값 불일치"로 판정한다(오류).
5. **2단 (분류)**:
   - 후보 자막이 아예 없으면 "자막 누락"(오류).
   - 값이 모두 일치하면 글자 일치율이 낮아도 정상.
   - 음성에 값이 없는 문장은 일치율(`difflib.SequenceMatcher(autojunk=False)`)이 낮으면 "표현 차이"로 **검수 필요**. 불일치로 판정하지 않는다.
6. 의미 유사도 판단(LLM, 문장 임베딩)은 쓰지 않는다(향후 확장).

| 음성 | 자막 | 기대 판정 |
|---|---|---|
| 3월 15일부터 신청하실 수 있습니다 | 신청 시작: 3월 15일 | 정상 (값 일치) |
| 오후 세 시 삼십 분까지 | 15:30까지 | 정상 (값 일치) |
| 신청 기간은 3월 15일까지입니다 | 신청 마감: 3월 16일 | 값 불일치 (오류) |
| 신청은 홈페이지에서 가능합니다 | 온라인 신청 가능 | 표현 차이 (검수 필요) |

### M2: 화면 글자↔음성

1. 1fps 샘플링, 가로 1280px로 축소, 직전 OCR 프레임과 차이가 작으면 건너뜀, 신뢰도 0.5 미만은 "판단 불가: 화면 확인 필요" 후보로 분리.
2. 연속 프레임의 유사도 0.85 이상 글자를 `ScreenText(text, t_start, t_end)`로 병합.
3. **제외 규칙** (지속 시간만으로 제외하지 않는다):
   - 자막과 일치하는 글자
   - 중요 정보가 없는 글자
   - 오래 표시되고(초기값: 영상 길이의 70% 이상) 중요 정보가 없으며 화면 모서리에 작게 있는 글자(로고·워터마크)
   - 오래 표시되지만 **중요 정보(전화번호, 신청 안내 등)가 있으면 제외하지 않는다.** 구간마다 반복 지적하지 않고 "영상 내내 표시됨"으로 한 건만 올리며, 영상 어디에서든 말해졌는지 확인한다.
4. **음성 대조** (2단계 창):
   - 가까운 창 `[t_start−5s, t_end+5s]`에 있으면 정상
   - 영상 다른 곳에서만 말했으면 **검수 필요** "다른 시점에 언급됨". 정보가 필요한 장면과 설명 시점이 어긋나면 이해하기 어려울 수 있으므로, 표시 시점과 설명 시점의 차이(초)를 상세 패널에 함께 보여 준다.
   - 영상 전체에서 말하지 않았으면 화면 전용 정보(오류)
5. 화면 글자와 음성의 값이 정규화 후 다르면 값 불일치(오류).

### M2-2: 화면 의존 표현 구간 안내

음성이 화면을 전제로 말하는 구간을 찾아, 화면해설이 필요한지 사람이 확인하도록 안내한다. 장면 분석은 하지 않고 받아쓰기 텍스트만 쓴다.

1. 규칙 기반 표현 목록을 `AnalysisConfig`에 둔다. **좁게 시작한다.** 초기 목록: "보시는 것처럼", "보시다시피", "보시는 바와 같이", "화면에서", "화면과 같이", "이쪽으로", "저쪽으로", "다음과 같이", "이렇게 하시면". "여기서", "이렇게" 단독처럼 일상 대화에 흔한 표현은 제외한다.
2. 받아쓰기 구간에서 표현이 발견되면 `IssueKind.SCREEN_DEPENDENT`, **검수 필요**로 안내한다. 문구: "화면을 봐야 이해되는 구간입니다. 화면해설이 필요한지 확인하세요."
3. 같은 구간에서 M2 화면 글자 대조로 이미 지적된 항목이 있으면 중복해서 올리지 않고 기존 지적에 표현을 덧붙인다.
4. 누락을 **판정**하지 않고 확인 대상을 **안내**한다. 상세 패널과 요약에서도 "확인 필요"로 표시한다.
5. 표현 목록은 평가 영상에서 거짓 지적 비율을 보고 조정한다.

### 임계값

모두 `AnalysisConfig`에 둔다. 위 숫자는 시작값이며, **Phase -1의 정답 데이터로만** 조정한다. STT·OCR 원시 결과는 영상 해시 기준으로 캐시하므로, 임계값을 바꿔도 재분석 없이 판정만 다시 돌린다.

- **Task 11**: `screen_check.py` (정상, 가까운 창, 먼 창, 화면 전용, 자막과 겹침, 워터마크, 영상 내내 표시되는 전화번호, 그래프 수치 "30%/60%"가 음성에 없는 경우)
- **Task 11-1**: `screen_dependent.py` (표현 검출, 일상 표현 오탐 방지, M2 지적과의 중복 병합을 가짜 STT 결과로 테스트. 예: "보시는 것처럼 상당히 증가했습니다", "이쪽으로 이동하시면 됩니다")

### Phase 3. 통합과 GUI (M3)

## 향후 확장

| 항목 | 내용 |
|---|---|
| 비문자 시각 정보 | 행동, 몸짓, 그래프 의미, 장면 변화의 설명 누락 점검 |
| 소리 정보 | 아래 기준을 적용해 효과음·화자 표시 점검 |
| 의미 유사도 | "표현 차이"를 LLM/임베딩으로 좁히기 (외부 전송 없이 로컬 모델로) |
| 사양 기반 자동 추천 | 배포 PC 사양 확인 후 코어·RAM 기준 등급표 도입 |
| 오프라인 패키징 | 모델을 함께 넣은 설치 패키지, 기관 망 정책 확인 (공모전 이후 기관 배포 단계) |

**소리 정보 적용 기준** (기능은 이번 범위 밖)

- 안전과 상황 이해에 필요한 소리(경고음, 화면 밖 소리, 화자 식별)는 우선순위가 높다.
- 분위기를 위한 배경음악처럼 이해에 영향이 적은 소리는 우선순위가 낮다.
- 효과음은 통념적인 표기를 쓴다.
- 자막에 정보를 과하게 넣지 않는다. 찾은 개수보다 적절성이 중요하다.

**실증 계획**: 장애인 당사자와 함께 일반인 시청자도 대상에 포함한다.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| 모델이 찾은 것을 정답으로 착각해 잘못된 기준 위에서 코드만 정교해짐 | 높음 | Phase -1을 코드보다 먼저 수행, 독립 평가 2인, 임계값은 정답으로만 조정 |
| 평가 영상이 적어 형식별 성능 차이를 설명하지 못함 | 중 | 형식이 다른 영상 3편, 결과를 형식별로 보고, 한계를 명시 |
| 정밀도 60%에서도 검수 시간이 줄지 않음 | 중 | 검수 시간·불필요한 확인 횟수 측정, 줄지 않으면 목표 재설정 |
| OCR 속도: easyocr는 CPU에서 프레임당 수 초라 20분 영상이 수십 분 걸릴 수 있음 | 높음 | Task 0에서 실측. 프레임 차이 기반 건너뛰기, 축소, 샘플 간격 조정, 엔진 교체 검토 |
| Whisper CPU 처리 시간, 저사양 CPU의 작은 모델은 한국어 정확도가 낮음 | 높음 | Task 0에서 가장 먼저 검증, 낮은 신뢰 구간은 "판단 불가"로 분리, 수동 모델 변경 허용 |
| 자막 없을 때 하단 글자를 자막으로 오분류 (이름·기관명 등) | 높음 | 영역 단위 판단, 편집자 확인 단계, 제외된 글자는 M2로 |
| OCR 생성 자막의 오류가 M1 결과를 왜곡 | 높음 | 이 모드의 M1 결과는 "검수 필요"로만 표시 |
| 자막이 발화를 그대로 옮기지 않아 글자 일치율 기반 판정이 거짓 지적을 만듦 | 높음 | 값 비교 우선 2단 구조, 표현 차이는 "검수 필요" |
| STT 오인식이 거짓 지적으로 이어짐 | 높음 | "판단 불가: 음성 확인 필요" 상태로 분리 |
| 영상 내내 표시되는 중요 정보(전화번호 등)를 워터마크로 오인해 제외 | 중 | 지속 시간만으로 제외하지 않음, 위치·내용 함께 고려 |
| 자막 영역과 일반 화면 글자 영역 분리 오류(자막 위치가 영상마다 다름) | 중 | 영역 비율을 설정으로 노출, 편집자 확인, 평가 영상으로 확인 |
| 한국어 수사·고유어 시각 변환 누락 | 높음 | 테스트 주도로 변환 표 확장, 못 맞춘 경우는 지적 쪽으로 기울여 사람이 기각 |
| M2가 "화면해설 점검"으로 과대 해석되어 심사에서 공격받음 | 중 | 기능 정의를 "화면 속 문자 정보의 음성 전달 점검 + 확인 필요 구간 안내"로 좁혀 쓰고, 비문자 시각 정보는 향후 확장으로 명시 |
| 화면 의존 표현 검출의 거짓 지적 (일상 표현 오탐) | 중 | 표현 목록을 좁게 시작, "검수 필요"로만 표시, 평가 영상으로 조정 |
| 영상 이용 조건·모델 라이선스 확인 누락 | 중 | 권리·데이터 처리 원칙, 평가 영상 출처·이용 조건 기록 |
| 자막이 SMI·CP949라 읽기 실패 | 중 | 인코딩 자동 감지, SMI 지원 여부 결정(미결정 D) |
| Windows 한글 경로에서 프레임 읽기 실패 (`cv2.imread` 등) | 중 | ffmpeg stdout 파이프 또는 `np.fromfile`+`cv2.imdecode`, 한글 경로 테스트 |
| whisper 환각(음악·무음에서 없는 문장) | 중 | VAD, `no_speech_prob` 필터 |
| 설치 용량(torch 포함 수 GB) | 중 | `onedir` 빌드, CPU 전용 torch |
| 개발 환경이 macOS라 Windows 동작·빌드 검증 불가, ffmpeg 미설치 | 확정 | 엔진은 Mac에서 테스트(ffmpeg 설치 필요), Phase 4와 Windows 전용 검증은 Windows PC에서 수행 |
| 거짓 지적이 많으면 편집자의 신뢰 하락 | 중 | 결과 상태 3분류, 기각이 쉬운 UI, 임계값 조정, 캐시로 빠른 재판정 |
| 오프라인/방화벽 환경(기관)에서 모델 다운로드 실패 | 높음(기관 환경) | 공모전 범위에서는 모델 경로 설정과 다운로드 실패 메시지만 제공. 오프라인 패키징은 기관 배포 단계에서 보완 |
